Reference route: one PDF click

This is a reference route, not a record of an interactive code tour.

  1. src/canvas-listener.js — search for document.addEventListener('click'. Recognizes supported course-file links, prevents the preview, and sends OPEN_PDF. Ctrl decides foreground versus background.
  2. src/background.js — route validates the sender, saves an opaque request descriptor in session storage, then creates an independent extension tab.
  3. src/viewer/viewer.js — open resolves that descriptor, calls loadCanvasPdf in src/file-loader.js, and supplies bytes to bundled PDF.js. It also computes document identity before worker transfer and loads saved annotations.

External service: Utah Canvas, using the existing signed-in session. Local storage: per-document annotations and profile-wide note presets. PDF.js renders locally; there is no application backend.

To change this, start here

  • Eligible PDF clicks: src/canvas-listener.js, fileId and evidence; regression cases in tests/listener.test.js.
  • Zoom/search/page controls: src/viewer/reader-controls.js, wireReaderControls.
  • Sidebar actions: src/viewer/annotations-ui.js, wireAnnotations.
  • Highlight navigation and on-page marks: src/viewer/page-marks.js, scrollToHighlight and wirePageMarks. Saved normalized coordinates are converted to the current PDF viewport and centered without changing zoom.
  • Saved annotation identity: src/viewer/annotation-store.js, documentIdentity and createAnnotationStore; appearance presets in src/viewer/note-styles.js.

A practice to reuse

The first checklist slice tested the risky part—authenticated Canvas access—before building the complete reader. Real testing exposed folder-link and startup problems. Later, automated regression checks in tests/listener.test.js protected folder support and dashboard exclusion. For another project, first prove the smallest real workflow that exercises the biggest uncertainty; pair automated checks with testing in the actual environment.

Evidence limits: automated control and storage tests cannot establish physical touchpad behavior or authenticated campus compatibility. Those were checked by the user in Chrome.

Run it again

Run npm ci, npm test, then npm run build. Load dist through Chrome’s Load unpacked button, refresh signed-in Utah Canvas, and click a PDF. After changes, rebuild and reload the extension, then open a fresh PDF tab.
